KING OS V3.2.0 — DEPLOY (22.10.2026)

НАЧАЛО ОТСЧЁТА
19.10.2026 (понедельник). Недельные нормативы 60 ч работы / 4 силовые действуют уже на неделю 19–25 октября. История тренировок и записей до 19 октября сохраняется в базе, но в календаре Tracker не показывается.

ИЗМЕНЕНИЯ
• Спорт V3.1: Push A (19), Pull A (20), Push B (20+ДС), Pull B (21+ДС), всего 80 рабочих подходов, 5 суперсетов, 2 дроп-сета, 21s; RIR не записывается. История завершённых тренировок сохраняется.
• День: для идеального дня обязательны работа, спорт (силовая или отметка «Восстановление по плану»), чтение не менее 15 мин, режим 00:00–08:00, дисциплина. Выходной отменяет ежедневные нормы работы/спорта/чтения/сна, но не дисциплину. Недельные нормативы сохраняются.
• «Восстановление по плану» в редактировании дня, если в этот день нет силовой. Не считается за тренировку при подсчёте 4 силовых.
• Раздел «Обучение»: сначала список направлений, далее спортивная программа на 54 темы (можно добавлять новые курсы в будущих версиях).
• Постулаты: отдельные карточки, визуально разделённые кнопки.
• Tracker: мастурбация — число полных дней воздержания; «Без порно» — по подтверждённой пользователем дате отсчёта 18.10.2026, на утро 22.10 счётчик показывает 4 завершённых дня при отсутствии отмеченных нарушений. Показаны 19, 20 и 21 октября. Удалена строка о полосах.
• Экспорт JSON оставлен полным: все факты, заметки и история, без потерь.

УСТАНОВКА
1. В СТАРОЙ версии King OS на устройстве с записями: ⚙ → Экспорт JSON. Отложить резервную копию в надёжное место.
2. Из ZIP загрузить index.html, sw.js, manifest.webmanifest, icon-192.png, icon-512.png и .nojekyll в корень репозитория GitHub Pages с заменой файлов.
3. После публикации проверить версию V3.2.0 возле даты. Если PWA показывает старую версию, открыть https://everyf-web.github.io/king-os/?repair=1 .
4. Импорт JSON не требуется, если пользователь открывает то же приложение в том же браузере и его локальные записи сохранились.

ХРАНЕНИЕ
Ключ localStorage king_os_v1 неизменен. Перенос из V3.1.1 в V3.2.0 однократный и совместим с историческими снимками тренировок. Локальное хранилище может быть очищено браузером/пользователем; экспорт JSON хранить отдельно. При росте базы до нескольких МБ целесообразно перенести данные в IndexedDB / облако.
